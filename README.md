# МБМ-Транс — версия 3

Готовая статическая версия сайта `mbm-trans.ru` с одним same-origin
PHP-обработчиком заявок. Сайт рассчитан на размещение у российского хостинг-
провайдера; персональные данные формы не отправляются в Cloudflare, Telegram,
Google или другие внешние API.

## Локальный просмотр

```bash
python3 -m http.server 4173 --bind 0.0.0.0
```

На этом сервере форма работает только в безопасном режиме предпросмотра и не
отправляет введённые данные. PHP запускается только после размещения на хостинге.

## Что переносить на боевой хостинг

Загружать нужно только:

- `index.html`;
- страницы `*.html` из корня;
- папку `assets/`;
- папку `api/leads/`;
- `.htaccess`, `404.html`, `site.webmanifest`;
- `favicon.ico`, `robots.txt`, `sitemap.xml`.

Не загружать: `.git/`, `.design-director/`, `old-site-backup-*`, архивы `*.zip`,
`cloudflare/`, `build_pages.py`, `modx-preview-mbm-2026/`, `screenshots-v2/`,
`tmp/`, `tools/`, `telegram-*.php`, `telegram-config.example.php` и
`mbm-lead-mail.php`. Эти файлы сохранены только для истории и локальной работы.

## Заявки

Формы отправляют `POST` на `/api/leads/`. Обработчик:

- принимает запросы только с того же сайта;
- валидирует имя, телефон, e-mail и согласие;
- использует honeypot и проверку времени заполнения;
- не делает внешних HTTP-запросов и не сохраняет заявки в файлах;
- передаёт письмо локальной почтовой системе российского хостинга через `mail()`.

Перед публикацией в панели хостинга задать:

- `MBM_LEAD_RECIPIENT` — адрес получателя, по умолчанию `info@mbm-trans.ru`;
- `MBM_LEAD_FROM` — адрес отправителя на домене сайта, рекомендуется
  `site@mbm-trans.ru`.

Хостинг и почтовый сервер получателя должны находиться в России. Для временного
размещения обработчик совместим с PHP 5.5 текущего ValueHost. После переноса на
новый российский сервер рекомендуется использовать поддерживаемую версию PHP
8.2+ и настроенную отправку почты с домена `mbm-trans.ru`.

## SEO и адреса страниц

- основной адрес сайта: `https://mbm-trans.ru/` без `www`;
- `.htaccess` включает HTTPS, единый адрес главной, 301-редиректы старых
  страниц «О компании», «Контакты» и «Клиенты», а также собственную страницу 404;
- индексируемые страницы перечислены в `sitemap.xml`;
- служебные страницы и старые отдельные разделы помечены `noindex`;
- на страницах есть canonical, Open Graph, Twitter Card и Schema.org JSON-LD;
- `assets/og-cover.jpg` — актуальная обложка ссылки 1200×630;
- `site.webmanifest` и иконки 192×192/512×512 подготовлены для телефона.

После размещения нужно добавить сайт в Яндекс Вебмастер и Google Search
Console, отправить `https://mbm-trans.ru/sitemap.xml`, проверить 301-редиректы,
страницу 404 и отображение новой обложки ссылки.

## Проверка перед переключением домена

1. Убедиться, что локальные копии `../original`,
   `old-site-backup-2026-06-14` и история Git доступны. Повторную локальную
   копию создавать не нужно.
2. Если на старом хостинге есть отдельная база или серверные настройки,
   экспортировать их из панели непосредственно перед переключением.
3. Развернуть эту версию на временном российском поддомене с HTTPS.
4. Проверить главную, четыре услуги, проекты и политику на телефоне и компьютере.
5. Отправить тестовую заявку и убедиться, что письмо пришло без попадания в спам.
6. Проверить адрес отправителя, SPF, DKIM и DMARC в панели почты.
7. Убедиться, что `/api/leads/` отвечает `405` на `GET` и принимает только `POST`.
8. Проверить `/sitemap.xml`, `/robots.txt`, случайный несуществующий URL и
   редиректы со старых страниц.
9. Переключить домен, включить автоматический сертификат и повторить проверку.
10. Старую версию не удалять до окончания контрольного периода.

## Важное

Папка `cloudflare/` — только архив прежнего эксперимента. Она не используется
активными страницами и не должна попадать на боевой сервер.

Файл `build_pages.py` — устаревший генератор предыдущего дизайна. Его нельзя
запускать поверх актуальных HTML-файлов.
